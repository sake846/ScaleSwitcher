# Issue タイトル案

`設定画面と OSD を共通 UI 指針に合わせて再設計する`

## 背景

ScaleSwitcher、CtrlHanabi、copi2ctrl を同じ製品群として認識できるよう、共通の情報階層、余白、タイポグラフィ、状態表現、アクセシビリティ基準を導入したい。

現状の ScaleSwitcher は、設定が単一の縦並びで、ウィンドウサイズが `300 x 420` に固定されている。表示名、切り替え対象、倍率という意味上のまとまりや補足説明が弱く、長い翻訳や高い表示倍率にも余裕が少ない。また、OSD は固定色・固定フォントサイズのため、テーマやアクセシビリティ設定への追従方針を明確にしたい。

共通仕様は ScaleSwitcher リポジトリの `docs/ui-unification/README.md` を基準とする。

## 目的

- Windows ネイティブな、コンパクトで読みやすい設定画面にする
- 他 2 アプリと同じ「ヘッダー → 設定セクション → フッター」の構造にする
- ライト／ダーク、高 DPI、キーボード、日英表示に耐える UI にする
- 既存のトレイ中心の素早い操作と、設定ファイルの互換性を維持する

## 対象範囲

### Phase 1: 基盤と設定画面

- [ ] `App.xaml` に共通トークン相当の Brush、Spacing、CornerRadius、TextStyle、ControlStyle を定義する
- [ ] 固定の `Height="420" Width="300"` をやめ、`MinWidth`／`MinHeight` とコンテンツに応じたレイアウトへ移行する
- [ ] 設定画面を次の 3 セクションに再構成する
  - **切り替え対象**: 対象ディスプレイ
  - **表示名**: 「表示名を変更」と入力欄
  - **切り替える倍率**: 倍率の複数選択と短い説明
- [ ] 冒頭にタイトルと「左クリックまたはショートカットで切り替える内容を設定します」相当の説明を追加する
- [ ] フッターに「キャンセル」「保存」を並べ、保存を主ボタンにする
- [ ] `Escape` はキャンセル、既定ボタンは保存とし、自然な Tab 順を設定する
- [ ] 表示名を変更しない場合も入力欄は残して無効化し、関連性を伝える
- [ ] 倍率を 1 件も選ばず保存しようとした場合は、保存せず項目近くに理由と対処を表示する
- [ ] 設定画面の末尾に「このアプリについて」セクションを設け、製品名と実行中のプログラムバージョンを表示する
- [ ] Demod006_lora と同様に、リポジトリ直下へ 1 行形式の `version.txt` を追加し、バージョンの唯一の情報源にする
- [ ] `version.txt` をビルド出力・発行物へコピーする設定を `.csproj` に追加する
- [ ] 設定画面では実行ファイルと同じ配置先を基準に `version.txt` を読み込み、前後の空白と改行を除いた値を表示する
- [ ] `version.txt` がない、空、または読み込めない場合は、例外で終了せず「不明」／`Unknown` と表示する

### Phase 2: トレイメニューと OSD

- [ ] トレイメニューの並びを「ディスプレイ操作」「動作設定」「アプリ操作」に区切る
- [ ] チェック項目と排他的な選択項目を区別し、キーボード切り替え方式はラジオ選択として認識できる表示にする
- [ ] `Scale`／`スケーリング` などの用語を設定画面、メニュー、README 間で統一する
- [ ] OSD の背景、文字色、角丸、余白を共通トークンへ寄せる
- [ ] OSD の 48 px 固定文字を基準値＋表示倍率に追従する方式へ変更し、長い表示名でも画面外へ出ないようにする
- [ ] OS のアニメーション設定を尊重し、表示時間やフェードを追加する場合も操作を妨げない

### Phase 3: ローカライズと品質確認

- [ ] UI 文言をリソースとして整理し、ViewModel が個別の見た目用文言を抱えすぎない構成を検討する
- [ ] `Primary` が日本語 UI に残らないよう、ディスプレイ名の状態表記もローカライズする
- [ ] 日本語／英語、ライト／ダーク、100%／150%／200% でスクリーンショット比較を行う
- [ ] UI Automation の Name、Role、State を ComboBox、CheckBox、TextBox、Button に設定・確認する

## 対象外

- DPI／解像度切り替えロジックの仕様変更
- 設定 JSON のキー変更や既存ユーザー設定の破棄
- トレイ常駐というアプリ構造の変更
- 共通 UI フレームワークや大型サードパーティライブラリの導入

## 受け入れ条件

- [ ] 設定画面が共通の「ヘッダー → 3 セクション → フッター」構造になっている
- [ ] ウィンドウを初期表示した時点で主操作が見え、200% 表示でも操作不能にならない
- [ ] 保存、キャンセル、ウィンドウを閉じる操作の結果が一貫している
- [ ] 倍率未選択などの無効状態を、色だけに頼らず説明できる
- [ ] Tab／Shift+Tab の順序が視覚順と一致し、Enter／Space／Escape で操作できる
- [ ] 日本語／英語およびライト／ダークで文字切れ・低コントラストがない
- [ ] 設定画面で表示されるバージョンが、実行ファイルに同梱された `version.txt` の内容と一致する
- [ ] 開発ビルドと発行物の両方に `version.txt` が含まれている
- [ ] トレイの左クリック、キーボード切り替え、DPI／解像度メニューが従来どおり動作する
- [ ] 既存の `settings.json` をそのまま読み込み、保存後も既存項目が失われない

## 実装メモ

- WPF 標準コントロールを優先し、色の直書きは Resource 経由へ移す。
- Windows Forms のトレイメニューは WPF と完全に同じ描画にせず、構造・用語・状態表現を合わせる。
- 見た目の変更と機能ロジックの変更を別 PR にするとレビューしやすい。
